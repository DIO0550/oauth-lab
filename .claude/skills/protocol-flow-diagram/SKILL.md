# Protocol Flow Diagram Generator

認証・認可プロトコルの教育用SVGフロー図を生成するスキル。**Phase分割型レイアウト**で、複雑なプロトコルフローを段階的に視覚化する。

## ワークフロー

1. ユーザーからプロトコルタイプを受け取る（例: `oauth2-authorization-code`, `oidc`, `saml`）
2. `references/protocol-templates.md` でプロトコルに対応するPhase構成・アクター・ステップを確認
3. `references/svg-components.md` と `references/design-system.md` を参照
4. プロトコルの内容はClaudeの知識を使い、Phase分割型レイアウトに沿ってSVGを生成
5. `/mnt/user-data/outputs/{protocol-type}-flow.svg` に出力
6. `present_files` で提示

## 出力ファイル構成

| ファイル | 内容 |
|---------|------|
| `{protocol}-flow.svg` | Phase分割型フロー図（各Phaseにアクター2x2グリッド + 矢印 + 右サイドバー） |

## コアコンセプト: Phase分割型レイアウト

### なぜPhase分割か

プロトコルフローは多くのステップがあり、1枚の図に全矢印を描くと重なり・交差が発生する。Phase分割型では：

- **同じ4アクターの2x2グリッドをPhaseごとに繰り返す**
- 各Phaseはそのステップの矢印だけ描画（2〜3本）
- 非関連アクターはグレーアウト（破線ボックス）
- **矢印の重なりがゼロ**になる

### レイアウト構造（1 Phase分）

```
┌─────────────────────────────────────────────┬──────────────────────┐
│  Phase N  フェーズ名                          │  全体フロー           │
│                                              │  ① dim               │
│  ┌──────┐             ┌──────┐              │  ② dim               │
│  │Owner │  ──③──→    │Auth  │              │  ③ ★ACTIVE★          │
│  │      │  ←──④──    │Server│              │  ④ ★ACTIVE★          │
│  └──────┘             └──────┘              │  ⑤ ★ACTIVE★          │
│                                              │  ⑥ dim               │
│  ┌──────┐             ┌ ─ ─ ─┐             │  ⑦ dim               │
│  │Client│  ←──⑤──    │ Res  │ (dimmed)     │  ⑧ dim               │
│  │      │             └ ─ ─ ─┘             │                      │
│  └──────┘                                    │  凡例                 │
│                                              │  セキュリティポイント   │
│  [説明ボックス: パラメータ/コード例]            │                      │
├─────────────────────────────────────────────┴──────────────────────┤
│  --- Phase区切り線 (破線) ---                                        │
```

### アクター2x2グリッド座標

```
カードサイズ: 110 x 130px
左列 x=55,  右列 x=530   → 間隔 365px（矢印・説明用の空間）
上段 y=base+70, 下段 y=base+310  → 間隔 110px

アクター配置パターン（プロトコルごとに変更可能）:
  OAuth 2.0:     左上=Owner, 右上=AuthServer, 左下=Client, 右下=ResourceServer
  SAML:          左上=User, 右上=IdP, 左下=SP, 右下=(なし or 属性ストア)
  OpenID Connect: 左上=EndUser, 右上=OPサーバー, 左下=RPクライアント, 右下=UserInfo
```

### 重要な設計ルール

1. **viewBox幅**: `1100` 固定。図エリア 700px + サイドバー 340px + 余白
2. **viewBox高さ**: `Phase数 × 720 + ヘッダー80` で計算。4 Phaseなら約 3200
3. **カードサイズ**: 110x130px で統一（`<symbol>` で定義、`<use>` で再利用）
4. **説明ボックス配置**: アクターカードに被らないこと。中央の空間（x=170〜524の範囲）に配置
5. **矢印ルーティング**: 水平（上段同士・下段同士）or 斜め（左下↔右上）。垂直は左辺のみ
6. **グレーアウト**: 非関連アクターは `fill="#131a2b" stroke="#1e293b" stroke-dasharray="5,4"` の破線ボックス
7. **サイドバー**: 右 x=740, 幅340px。現在Phaseのステップのみハイライト背景（色8%透過 + stroke）
8. **Phase 1のサイドバーにのみ**凡例とセキュリティポイントを含める

### カラーコーディング（プロトコルフロー用）

```
ユーザー操作:      #a855f7 (紫)
フロントチャネル:   #22d3ee (シアン)  stroke-dasharray="9,4"
認可サーバー応答:   #f59e0b (アンバー)  stroke-dasharray="8,4"

```

### デザインシステム

色、フォント、間隔などの定数は `references/design-system.md` を参照。

### プロトコルテンプレート

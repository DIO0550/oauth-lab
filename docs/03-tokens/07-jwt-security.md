# JWT セキュリティベストプラクティス（RFC 8725）

## 概要

RFC 8725 は、JWT の実装における**よくある脆弱性と対策**をまとめた文書です。JWT を使う全ての開発者が知っておくべき内容です。

## 主要な攻撃と対策

### 1. alg: none 攻撃

**攻撃**: Header の `alg` を `none` に変更し、署名検証をバイパス:

```json
// 攻撃者が Header を改ざん
{ "alg": "none", "typ": "JWT" }
```

**対策**: `alg: none` を**常に拒否**する:

```
✅ サーバー側で許可するアルゴリズムを明示的にリスト化
✅ alg: none は本番環境で絶対に受け入れない
❌ JWT の Header に書かれた alg をそのまま信頼しない
```

### 2. アルゴリズム混同攻撃

**攻撃**: RS256（非対称鍵）で検証するサーバーに対し、HS256（対称鍵）の JWT を送り、公開鍵を HMAC の共有鍵として使わせる:

```
サーバーの公開鍵: public_key（公開情報）
攻撃者: HS256 で public_key を秘密鍵として署名
サーバー: alg=HS256 を見て public_key で HMAC 検証 → 成功してしまう
```

**対策**:

```
✅ 検証時のアルゴリズムをサーバー側で固定（JWT Header を信頼しない）
✅ 鍵ごとに許可されたアルゴリズムを紐づける
❌ JWT の alg に基づいて検証アルゴリズムを動的に切り替えない
```

### 3. kid インジェクション

**攻撃**: `kid` パラメータを悪用してファイルシステムやデータベースにアクセス:

```json
// SQL インジェクション
{ "kid": "key-1' OR '1'='1", "alg": "HS256" }

// パストラバーサル
{ "kid": "../../etc/passwd", "alg": "HS256" }
```

**対策**:

```
✅ kid の値をサニタイズ・バリデーション
✅ 鍵の取得を固定の JWKS エンドポイントに限定
❌ kid を直接ファイルパスやSQLクエリに使用しない
```

### 4. トークン置換攻撃

**攻撃**: あるサービス向けの JWT を別のサービスで使い回す:

```
Service A 向けの JWT を取得
→ Service B に送信
→ 署名は有効なので受け入れられてしまう
```

**対策**:

```
✅ aud（Audience）クレームを必ず検証
✅ iss（Issuer）クレームを必ず検証
✅ 用途ごとに typ を使い分け（"at+jwt", "dpop+jwt" 等）
```

### 5. トークン再利用（リプレイ）攻撃

**攻撃**: 傍受した JWT を再送信:

```
正規ユーザー → サーバー: JWT を送信
攻撃者: JWT を傍受
攻撃者 → サーバー: 同じ JWT を再送信
```

**対策**:

```
✅ exp（有効期限）を短く設定
✅ jti（JWT ID）でリプレイを検知
✅ DPoP で送信者を制約
✅ TLS を使用して傍受を防止
```

## JWT 検証チェックリスト

```
□ alg が許可リストに含まれるか（none を拒否）
□ 署名が有効か
□ exp が現在時刻より後か
□ nbf（Not Before）が現在時刻より前か（存在する場合）
□ iss が期待する発行者と一致するか
□ aud が自分の識別子と一致するか
□ iat が妥当な範囲か
□ typ が期待するタイプと一致するか（存在する場合）
```

## ベストプラクティスまとめ

### 発行時

| プラクティス | 説明 |
|-------------|------|
| 短い有効期限 | アクセストークンは 5〜60 分 |
| 必要最小限のクレーム | 機密情報を Payload に含めない |
| 適切な alg | RS256 以上、HS256 は内部用のみ |
| kid を含める | 鍵ローテーションに対応 |
| typ を含める | トークンの種類を明示 |

### 検証時

| プラクティス | 説明 |
|-------------|------|
| alg を固定 | JWT Header を信頼せずサーバー側で指定 |
| 全クレーム検証 | iss, aud, exp, nbf を全て検証 |
| JWKS キャッシュ | 毎回取得せずキャッシュ（DoS 防止） |
| エラー情報の非公開 | 検証失敗の詳細を返さない |
| 最大サイズ制限 | 巨大な JWT を拒否（DoS 防止） |

### 保存・送信

| プラクティス | 説明 |
|-------------|------|
| TLS 必須 | JWT を平文で送信しない |
| HttpOnly Cookie | XSS による窃取を防止 |
| ログに含めない | JWT をログに出力しない |
| 機密性が必要なら JWE | 署名だけでなく暗号化も検討 |
